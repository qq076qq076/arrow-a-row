## 為何不可宣告完成

M0 工程 Gate 要求「Unity 6.3 LTS 專案、asmdef、CI 最小編譯、Android/iOS 空殼」，且至少能在乾淨環境建置 Android debug。手寫一個未經 Unity Editor 開啟的資料夾無法驗證 `ProjectVersion.txt`、相容 package lock、Android toolchain 或 build；因此不建立假專案、不虛報完成。

## 解除阻塞所需輸入

1. 安裝 Unity Hub 與 **Unity 6.3 LTS** 的指定精確 patch（含 Android Build Support、Android SDK/NDK/OpenJDK、iOS Build Support）。
2. 將 Unity batchmode executable 加入 PATH，或提供其絕對路徑。
3. 決定 CI 平台帳號／repository secret 的管理者；不需要在此提交任何憑證。
4. PM 指定系統／關卡／數值設計的具名 owner，作為之後 content change 的核准者。

## 解除後工程工作清單

1. 建立 Unity 6.3 LTS URP mobile 專案、直式設定、iOS 15+/Android 10+。
2. 建立 `Arrow.Domain`、`Application`、`Content`、`Infrastructure`、`Presentation`、`Composition` asmdef。
3. 建立 `Bootstrap`、`Shell`、`Run` scene 與空的 composition root。
4. 依 `M0-ART-001` 建 typed asset ID、placeholder Prefab、Addressables label。
5. 加入 Input System、Addressables、Test Framework，鎖定 manifest/lock。
6. 建立最小 EditMode test 與 Android debug batchmode build；將完整命令和輸出寫入下一份完成紀錄。

## 對 QA 的影響

QA 的 M0 裝置矩陣與測試文件可獨立完成，但無法完成「可安裝 smoke baseline」。QA 應先建立文件與案例，並將真機 build 驗收標記為等待 ENG M0 解除。
