# 介面設計師：UI/UX 設計交付文件

版本：0.1｜平台：iOS／Android 直式優先｜唯一流程基線：[畫面流程與 UI 規格](../Arrow-a-Row-畫面流程與UI規格.md)

## 1. 設計責任

介面設計師負責讓玩家不靠說明也能開始、操控、選 Gate、理解 Build、完成結算與安全恢復 Run；負責 wireframe、視覺系統、互動狀態、可近用性、文案容器與設計驗收，不負責最終傷害／經濟數值。

## 2. 必交畫面與優先級

| 優先 | 畫面 | 交付層級 |
| --- | --- | --- |
| P0 | 啟動、主選單、新局載入、跑圖 HUD、暫停、Boss 三選一、死亡／勝利結算 | 高保真稿、互動原型、標註。 |
| P0 | 商店、設定、前後台恢復、危險確認、錯誤提示 | 高保真稿、所有 state。 |
| P1 | 成就、圖鑑、無盡模式入口 | 高保真稿或清楚 wireframe。 |
| P1 | 平板／橫式適配、PC fallback | 響應式規則與關鍵畫面。 |

## 3. 版面與觸控系統

- 基準畫板 1080×1920，安全內容區以 iPhone 瀏海機與 Android 挖孔／手勢機各出一版；另出 720×1280、平板 4:3、橫式驗證稿。
- 使用 8 dp spacing system；主要 CTA 高度 ≥52 dp，其他可點元件 ≥48×48 dp，目標間距 ≥8 dp。
- 拖曳主區是 Run 畫面的非 UI 區；暫停與 Build 按鈕置於拇指不易誤觸的 safe corner，不能用透明全屏按鈕蓋住拖曳區。
- 所有關鍵資訊需以色彩 + 圖示／形狀 + 文字三種中至少兩種傳達。正負 Gate 不能只用綠／紅。
- 背景特效、傷害數字與彈幕不得使 Gate、Boss 預警、HP 低血提示失去對比；設計稿須列各狀態的最小對比與 z-order。

## 4. Run HUD 詳細規格

| 元件 | 必須顯示 | 互動／狀態 |
| --- | --- | --- |
| HP | `目前／最大`、血條、護盾 | 低於 30% 有圖形脈動；不僅變紅。 |
| 章節 | 章名／進度 | Boss 時改為 Boss 名與血條。 |
| 分數／金幣 | 即時總值、`+N` 回饋 | 不可遮擋 Gate。 |
| Build 快覽 | 4 類最多圖示與 stack | 點按開暫停後的 Build 詳情。 |
| 暫停 | `Ⅱ` 圖示按鈕 | 48 dp；點下立即視覺回饋。 |
| Gate | 名稱、精確效果、稀有度、風險 | 2.5 秒前可讀；選中後另一路明顯失效。 |

## 5. 關鍵互動規格

### Boss 獎勵

三張卡左中右固定排列；一次點按只展開詳情／選取外框，第二次點同卡或明確 `選擇` 才確認。卡面必有稀有度、名稱、現有→新層數、精確數值變化。重擲按鈕永遠顯示金幣成本與不足狀態。

### 商店

商品卡分頁橫向捲動、商品直向捲動；卡面先顯示目前級別、下一級變化、成本。購買後須等交易成功才動畫餘額與級別；錯誤顯示可行動文案。

### 前後台

回到前景必顯示「已自動暫停」，玩家點 `繼續` 才進遊戲。不得直接恢復、不得因手指仍接觸螢幕而位移。

## 6. Design System 交付

建立 Figma／同級設計庫，包含色彩 token、字體、8dp 間距、icon grid、陰影、圓角、字級、按鈕六狀態、卡片、tab、slider、modal、toast、progress、tooltip、skeleton loading。所有 token 有語意名（`surface-primary`、`action-danger`），不可用 `blue-3` 作產品語意。

每個元件需列：用途、變體、default/hover/focus/pressed/disabled/locked/selected、最小尺寸、內容溢出、觸控行為、accessibility label、工程對應 UXML/USS 元件。

## 7. 工程交付與驗收

交付包含：畫面連結、annotated spec、圖片／SVG 原檔、icon 命名、字體授權、切圖倍率、localization 最大字長、動畫時長與 easing、state matrix、redline、QA checklist。工程實作後，UI 設計師以真機 720p、1080p、不同 safe area、字級 150%、繁中／英文驗收。

成功條件：5 名新手中 4 名能單手過首門；卡片／放棄 Run 無誤觸；所有 UI 可在安全區看到；色弱模式不失資訊；低階機降特效後仍可讀。
