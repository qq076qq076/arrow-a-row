# 工程師：實作工作包與接口規格

版本：0.1｜主技術基線：[技術設計與程式規範](../Arrow-a-Row-技術設計與程式規範.md)｜本文件是工程工作拆解與跨職能接口，不取代技術規範。

## 1. 工程責任與非責任

工程師負責將經核准的遊戲、UI、內容規格轉成可測、可恢復、可在手機瀏覽器／PWA 運作的產品；主責 Three.js、TypeScript、React、資料、IndexedDB、瀏覽器生命週期、工具、CI 與部署整合。工程師不自行新增玩法、美術風格或貨幣規則；發現規格衝突時建立 issue／RFC。

## 4. Run 實作契約

`RunStateMachine` 是狀態唯一權威；只接受 command，不讓 React UI／Three.js Object3D 直接切 state。simulation 固定 30 Hz，呈現可 30／60 FPS。tick 順序固定為：Input → Movement → Spawn → Target → Fire → Projectile → Collision → Combat → State checks → Events。任何新增步驟必更新 deterministic test。

每個 mutating command 必具 idempotency：Gate=`runId:choiceGroupId`；Reward=`runId:bossId:rewardIndex`；Purchase=`profileId:transactionId`；Settlement=`runId:outcome`。重複呼叫回傳既有成功結果或明確錯誤，不可再次扣／加資源。

## 5. 工程測試與除錯工具

- 開發版提供 seed 輸入、下一組 Gate／Reward 預覽、強制 Boss、加金幣、模擬背景、慢速 tick、event log 匯出；release build 全移除或以開發旗標保護。
- 對每個 P0 bug，先加 regression test 再修。Domain 規則在 EditMode 測；Input、Pool、Scene、生命周期在 PlayMode／真機測。
- `RunStateHash` 每 60 tick 記錄於 QA build；差異輸出最早 mismatch tick。
- Logs 不寫入玩家 token／ID；所有 error 含 error code、run id、content version、build SHA。

## 6. PR 完成檢查

工程 PR 必附：需求連結、設計截圖或資料 diff、架構影響、migration（若有）、測試命令與結果、手機瀏覽器／Three.js profiler 證據（若熱路徑改動）、rollback／feature flag。不得把 package upgrade、GLB 大量重匯出、內容變更與功能混在一張 PR。
