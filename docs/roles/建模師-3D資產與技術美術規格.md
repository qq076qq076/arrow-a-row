# 建模師：3D 資產與技術美術規格

版本：0.1｜平台：iOS／Android｜目標：以低成本、高清楚度、可量產的原創 3D 資產支援直式 Roguelite 戰鬥。

## 1. 美術方向與責任

視覺關鍵字：**明亮奇幻、可讀的形狀語言、織光原野、柔和材質、強化時明顯變化**。建模師負責角色、敵人、Boss、環境模組、動畫可用骨架、Prefab 組裝與 LOD／材質規格；UI 圖示與 VFX 細節由 UI／特效職能協作，但模型必提供清楚的掛點與遮罩。

禁止：寫實血腥、過度繁雜輪廓、與參考遊戲可辨識的角色／怪物造型、未授權素材、手機上難以讀取的微小裝飾。

## 2. 內容清單與交付順序

| 優先 | 資產 | 數量 | 驗收重點 |
| --- | --- | ---: | --- |
| P0 | 主角、箭、飛劍、命中／受擊掛點 | 1 套 | 直式鏡頭下清楚，支援所有 Build。 |
| P0 | 章 1 路徑 kit、4 普通敵人、Boss | 1 套 | 垂直切片可完整遊玩。 |
| P1 | 章 2、章 3 路徑 kit、敵人、Boss | 2 套 | 與章 1 重用 shader／骨架／材質規則。 |
| P1 | 夥伴 3 種、精英變體、可破壞物 | 7+ | 不影響主角／敵彈可讀性。 |
| P2 | 選單背景 idle、商店陳列、成就展示 | 視需求 | 低動態、可降級。 |

章節主題：晨線草原（圓潤、葉片、青綠金色）、鏡潮高架（弧面、晶體、靛藍銀色）、熾心熔庭（厚重、分段、紫琥珀）。詳見世界觀文件；資產名稱不可包含現有作品名。

## 3. 模型與貼圖規格

| 類型 | 三角形預算（LOD0） | 貼圖 | 材質數 | LOD |
| --- | ---: | --- | ---: | --- |
| 主角 | ≤8k | 1×1024 或 2×512 | ≤2 | LOD0/1。 |
| 普通敵人 | ≤3k | 1×512 | ≤1 | LOD0/1。 |
| 精英 | ≤4k | 1×512 | ≤2 | LOD0/1。 |
| Boss | ≤12k | 1×1024 | ≤3 | LOD0/1/2。 |
| 夥伴／飛劍 | ≤1.5k | atlas 512 | ≤1 | LOD0/1。 |
| 路段模組 | ≤2k／piece | atlas 1024 | ≤1 | LOD0/1。 |

- 目標為 Standard 手機；預算是上限，不是應用額度。任何超限要有 profile 證據與 Tech Lead 核准。
- 優先共用材質、atlas 與 GPU instancing。避免透明材質、即時反射、獨立高解析貼圖與非必要 normal map。
- Android 使用 ASTC 為優先壓縮策略，iOS 採平台適當壓縮；最終設定由工程 pipeline 決定。
- Pivot：角色／敵人置於腳底中心；投射物沿 +Z 前方；所有單位使用 meter，比例 1 Unity unit = 1m。

## 4. 骨架、動畫與掛點

| 物件 | 必需骨架／掛點 | 最低動畫 |
| --- | --- | --- |
| 主角 | Root、Hip、Spine、Head、左右手、BowSocket、SwordOrbitCenter、PetFollowPoint、HitPoint | idle、run、hurt、death、victory。 |
| 近戰敵 | Root、HitPoint | idle、move、attack telegraph、attack、hurt、death。 |
| 遠程敵 | Root、Muzzle、HitPoint | idle、move、aim/telegraph、fire、hurt、death。 |
| Boss | Root、Muzzle／多個攻擊點、HitPoint、SummonPoint | idle、move、3 招 telegraph+attack、phase、hurt、death。 |

- Root motion 關閉；移動由 simulation／工程控制。動畫只做表現，不能改變碰撞／傷害時機。
- 每個攻擊至少有 0.35 秒可見 telegraph；模型／動畫需留出明確的蓄力姿勢與亮點區。
- 統一 30 FPS animation sampling，除非動作需更高精度；loop clip 首尾無跳格。

## 5. Prefab 與命名

命名：`CHR_Seeker_A`、`ENM_MistRunner_A`、`BOS_MossCrown_A`、`ENV_Meadow_PathStraight_A`、`PRP_Gate_Common_A`。禁止 `final`、`new`、中文檔名、空格與重複版本號。

每個 Prefab 包含：Renderer、Animator（若適用）、明確 collider、`VisualAnchor`、LODGroup（若需）、材質引用、Addressables label。遊戲數值不放在 Prefab；碰撞層與 VFX socket 由 prefab 明示。不得留下攝影機、測試 script、missing reference、未使用 renderer。

## 6. 交付流程與驗收

```text
moodboard／形狀提案 → 灰盒比例審查 → 低模＋骨架 → 動畫／材質
→ Unity prefab 組裝 → 真機 profile → QA 視覺／碰撞驗收 → Addressables 入庫
```

每項交付需有：原始檔、匯出 FBX、貼圖來源、材質表、三角形／貼圖／材質統計、動畫列表、socket map、授權來源、Unity Prefab、真機截圖。視覺驗收：直式 1080×1920 中主角與敵人輪廓可分、Boss 預警不被材質吞沒、低特效模式仍讀得出攻擊與 Gate。

## 7. 技術美術品質閘門

- 不新增 shader variant 或透明疊層而未量測 draw call／GPU frame time。
- 所有資產經 import preset：scale、壓縮、mipmap、read/write、mesh compression、動畫壓縮一致。
- 每章可安全卸載；Addressables label 依 `chapter-01`、`shared-character`、`shared-vfx` 分組。
- 100 局 soak 後不得有材質遺失、pool 殘影、骨架 null、記憶體不回收。
